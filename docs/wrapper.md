# Обёртка над Keitaro

Обёртка хранит черновик состава офферов потока и публикует его в Keitaro только по явной команде. Пока черновик не отправлен, трекер не меняется. Источник поведения — ролик [keitaro wrapper - test](https://www.youtube.com/watch?v=jNloscEWCjA).

## Бизнес-процесс

Пользователь правит уже существующую кампанию в Keitaro. В кампании два вида потоков. Поток с офферами делит трафик между офферами по весам. Поток без офферов задаёт редирект и фильтры в самом трекере: обёртка такой поток хранит, а содержимое не разбирает.

Домен, группа и источник кампании остаются настройками Keitaro. Обёртка их не показывает и не меняет.

1. Пользователь нажимает **Fetch Streams**. Обёртка забирает все потоки кампании. У потока с офферами показывает офферы. Поток без офферов показывает как поток, без редиректа и фильтров.
2. Дальше правки живут в обёртке. Пользователь ищет оффер по id: интерфейс спрашивает API обёртки, API спрашивает Keitaro API. Новый оффер сразу получает равную долю с остальными активными. Поток становится жёлтым.
3. Удаление оставляет оффер в обёртке. Он сереет, вес становится 0%, запись уходит в архив. Вернуть его можно кнопкой **Bring back**. И удаление, и возврат снова делают поток жёлтым.
4. Вес можно запинить. Следующие добавления и удаления пересчитывают все веса, кроме запиненных. Активные веса в сумме дают 100%. Удалённый оффер в эту сумму не входит.
5. **Push to Keitaro** записывает в трекер текущие офферы и веса. До этой кнопки страница Keitaro показывает прежний состав.
6. **Cancel** на жёлтом потоке снимает офферы, добавленные до публикации. Привязка к потоку удаляется, сам оффер остаётся. Поток белеет: локальных изменений нет.
7. Если оффер удалили в самом Keitaro, следующий Fetch Streams оставляет его в обёртке. Он становится серым со статусом `removed`, как после ручного Remove, и его можно вернуть через Bring back.

### Состояния

| Сигнал | Значение |
| --- | --- |
| Белый поток | Опубликован, локальных изменений нет |
| Жёлтый поток | Есть изменения, которые ещё не ушли в Keitaro |
| Серый оффер | Статус `removed`, вес 0%, лежит в архиве, доступен Bring back |

### Фикстура для проверок

Одна кампания и два потока.

- Поток без офферов ловит Австралию и редиректит на Google.
- Поток с офферами ловит всех, кого не поймал первый, и делит трафик по трём офферам примерно по 33%. Четвёртый оффер появляется уже в обёртке.

## Тест-кейсы

### Импорт потоков

Fetch Streams собирает кампанию в обёртку. Потоки с офферами приходят вместе с офферами. Потоки без офферов приходят как потоки: редирект и фильтры остаются в Keitaro.

| ID | Шаги | Ожидание |
| --- | --- | --- |
| FS-01 | Открыть кампанию-фикстуру и нажать Fetch Streams. | В обёртку попадают оба потока кампании. |
| FS-02 | Fetch Streams на потоке, в котором в Keitaro уже лежат офферы. | Офферы этого потока видны в интерфейсе обёртки. |
| FS-03 | Fetch Streams на потоке без офферов. | Поток добавлен как поток. Редирект, фильтры и прочее содержимое в обёртке не показываются и не парсятся. |

### Добавление оффера

Выбор оффера идёт по id через API обёртки в Keitaro API. Добавление пересчитывает веса в черновике и помечает поток неопубликованным. В трекер состав попадает только после Push.

| ID | Шаги | Ожидание |
| --- | --- | --- |
| AD-01 | В выборе оффера ввести id существующего оффера. | Интерфейс ходит в API обёртки, API ходит в Keitaro API за офферами. Оффер находится, и его можно выбрать. |
| AD-02 | В потоке с 3 офферами выбрать найденный оффер и нажать добавить. Push не нажимать. | В интерфейсе 4 оффера, у каждого вес 25%. Поток жёлтый. |
| AD-03 | После AD-02 обновить страницу этой кампании в Keitaro. | В Keitaro по-прежнему 3 оффера. |

### Публикация

Push — единственный шаг, который переносит черновик офферов и весов в Keitaro.

| ID | Шаги | Ожидание |
| --- | --- | --- |
| PU-01 | На жёлтом потоке с локально добавленным оффером нажать Push to Keitaro. | В Keitaro те же 4 оффера и те же веса, что в интерфейсе обёртки. |

### Отмена черновика

Cancel выбрасывает офферы, добавленные после последней публикации, и возвращает поток в белое состояние. Keitaro при этом не меняется.

В субтитрах фраза про Cancel обрывается: «привязка офер останется, привязка удалится». Ниже ожидание собрано из неё и из слов «удалятся из нашей базы»: привязка к потоку удаляется, сам оффер остаётся.

| ID | Шаги | Ожидание |
| --- | --- | --- |
| CA-01 | Добавить оффер и, пока поток жёлтый и не опубликован, нажать Cancel. | Офферы, добавленные до публикации, снимаются с потока. Привязка к потоку удаляется, сам оффер остаётся. Поток из жёлтого становится белым. В Keitaro ничего не менялось. |

### Удаление и возврат

Remove не стирает оффер из обёртки. Он уходит в архив с нулевым весом. Bring back готовит возврат в поток, а в Keitaro оффер появляется снова только после публикации.

| ID | Шаги | Ожидание |
| --- | --- | --- |
| RM-01 | На любом оффере потока нажать Remove. Не публиковать. | Оффер серый, его доля 0%. Поток жёлтый. |
| RM-02 | Опубликовать поток после Remove. | Оффер исчезает из Keitaro. В обёртке он остаётся в архиве, серый, со статусом удалён. Доступна кнопка Bring back. |
| RM-03 | На архивном сером оффере нажать Bring back, затем опубликовать поток. | После Bring back поток снова жёлтый. После публикации оффер возвращается в поток. |

### Синхронизация с Keitaro

Обёртка помнит оффер, даже если его удалили в трекере. Следующий импорт переводит такую запись в тот же архив, что и ручной Remove.

| ID | Шаги | Ожидание |
| --- | --- | --- |
| SY-01 | В Keitaro удалить несколько офферов потока, сохранить изменения, затем в обёртке снова нажать Fetch Streams. | Офферы, которые обёртка уже знала и которых больше нет в Keitaro, остаются в обёртке. Они серые, статус `removed`. Bring back может вернуть такой оффер. |

### Веса

Активные незапиненные офферы делят 100% поровну. Запиненный вес пересчёт пропускает. Удалённый оффер получает 0% и в сумму не входит. В ролике после Bring back при запиненных 25% активны ещё два оффера; доли 37,5% выведены из этого правила, в речи назван сам пересчёт.

| ID | Шаги | Ожидание |
| --- | --- | --- |
| WT-01 | Запинить вес оффера на 25%, затем добавить или удалить другой оффер. | Пересчитываются веса всех офферов, кроме запиненного. Запиненный остаётся 25%. |
| WT-02 | При запиненном весе 25% нажать Bring back на удалённом оффере. После этого активны запиненный и ещё два оффера. | Запиненный вес остаётся 25%. Веса двух незапиненных офферов пересчитываются до 37,5% каждый. |
| WT-03 | Опубликовать поток из WT-02. | В Keitaro запиненный оффер остаётся 25%. Остальные активные офферы делятся поровну, сумма весов 100%. |
| WT-04 | Удалить один незапиненный оффер из потока, где ни один вес не запинен. | У удалённого оффера доля 0%. Оставшиеся активные офферы заново делят 100% поровну. |
